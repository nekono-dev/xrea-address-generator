# 発行・管理画面 要件定義書

## 1. 目的

転送アドレスの発行と管理を、1画面の簡素な操作で行えるようにする。ブラウザ標準の部品に頼らず、入力・選択・通知・確認のすべてを独自の部品で構成し、見た目と操作を統一する。

## 2. スコープ

### 2.1 対象

- 上端に固定した発行フォーム。
- 発行済みの一覧（絞り込み、並び替え、コピー、転送先の変更、削除）。
- 選択した値のブラウザへの保存と、次回の表示での復元。
- 幅680ピクセル未満のスマートフォン向けの表示。
- Proton Passのエントリ名の表示と、照合状態の通知。

### 2.2 対象外

- サーバ側の処理。
- 利用者の認証。
- Proton Passへの書き込み。
- アドレスへのメモの入力。

## 3. 前提

- なし

## 4. 機能要件

- FR-1: 名前・ドメイン・発行ボタン・転送先から成る発行フォームを、スクロールしても画面の上端に固定して表示する。
- FR-2: 名前または転送先の入力中にEnterを押すと発行を要求し、日本語入力の変換確定中は要求しない。
- FR-3: 名前が空のまま発行を要求し、応答のアドレスの行を強調表示して、その行までスクロールする。
- FR-4: ドメインを独自のドロップダウンで選択し、候補をサーバから取得し、最後に選んだドメインが候補にあれば次回の初期値にする。
- FR-5: 転送先を自由入力か候補から指定し、形式不正の入力では誤りを示して発行を無効にし、最後の有効な転送先を次回の初期値にする。
- FR-6: 一覧をドメインで絞り込み、アルファベット順の昇順と降順を切り替えて表示し、絞り込みと並び順を次回の表示で復元する。
- FR-7: 各行にアドレス・転送先・Proton Passのエントリ名を表示し、取得中は読み込み表示を出す。
- FR-8: コピーボタンでアドレスをクリップボードへ複製して通知し、削除ボタンで行内に確認を表示して確認後にだけ削除を要求する。
- FR-9: 各行の転送先を、行内の入力部品で自由入力か候補から指定して変更し、形式不正の入力では確定を無効にする。
- FR-10: Proton Passの照合状態を表示し、更新ボタンで再取得を要求し、再ログインの開始と完了を通知し、連携が無効のときは照合の表示を出さない。
- FR-11: サーバが返したエラーのメッセージを、通知として表示する。
- FR-12: ブラウザ標準の選択部品・確認ダイアログ・通知ダイアログを使わず、キーボードだけで全操作ができる。

## 5. 非機能要件

- NFR-1: 名前の入力欄・発行ボタン・ドメインの選択・転送先の入力欄の高さを、幅680ピクセル以上で38ピクセル、未満で44ピクセルにする。
- NFR-2: 幅360ピクセルの表示で、横スクロールを発生させない。
- NFR-3: 発行の成功応答から一覧への新しい行の表示までを、200ミリ秒以内に完了する。
- NFR-4: ドメインの候補リストと転送先の候補リストを開いたとき、見切れる項目の数を0にする。
- NFR-5: 幅680ピクセル未満の表示で、文字の大きさを幅680ピクセル以上の表示の1.2倍（本文15ピクセルを18ピクセル）にする。
- NFR-6: タッチ操作の端末と幅680ピクセル未満の表示で、文字入力欄の文字の大きさを16ピクセル以上にする。

## 6. 受け入れ条件

- AC-1 (FR-1): ページを下へ600ピクセルスクロールした後も、発行フォームの上端が画面の上端に位置する。
- AC-2 (FR-2): 名前欄でEnterを押すと発行の要求が1回送信され、変換確定中のEnterでは送信されない。
- AC-3 (FR-3): 名前が空の発行で、要求の名前が空のまま送信され、応答のアドレスの行が強調表示される。
- AC-4 (FR-4): ドメインを開くと取得済みの候補が並び、矢印キーとEnterで選択すると表示が切り替わる。
- AC-5 (FR-5): 形式不正の転送先で誤りが表示されて発行ボタンが無効になり、候補を選ぶと有効になる。
- AC-6 (FR-6): ドメインを選ぶとそのドメインの行だけが残り、降順への切り替えで並びが逆になる。
- AC-7 (FR-7): 行にアドレスと転送先とエントリ名が表示され、照合の取得中は読み込み表示が出る。
- AC-8 (FR-8): コピーボタンの押下でクリップボードにアドレスが入り、通知が表示される。
- AC-9 (FR-8): 削除ボタンの押下で行内に確認が出て、確認前には削除の要求が送信されず、エントリがある行では確認文にその名前が含まれる。
- AC-10 (FR-10): 更新ボタンの押下で再取得の要求が送信され、再ログイン中はバナーが表示されて完了後に通知される。
- AC-11 (FR-11): 発行の要求に409が返ると、応答のメッセージが通知に表示される。
- AC-12 (FR-12): 画面にネイティブの選択要素・ダイアログ要素・標準ダイアログの呼び出しが無く、キーボードだけで発行から削除まで操作できる。
- AC-13 (NFR-1): 4つの部品の描画後の高さが、幅900ピクセルで38ピクセル、幅360ピクセルで44ピクセルになる。
- AC-14 (NFR-2): 幅360ピクセルの表示で、文書の横幅が表示幅を超えない。
- AC-15 (NFR-3): 発行の成功応答から200ミリ秒以内に、新しい行が一覧に現れる。
- AC-16 (NFR-4): 幅900ピクセルと360ピクセルの両方で、両方の候補リストの全項目が最前面に表示される。
- AC-17 (FR-9): 行の変更ボタンで入力部品が開き、候補を選んで確定すると変更の要求が送信されて行の転送先が切り替わる。
- AC-18 (FR-9): 行内の入力部品で形式不正の転送先を入力すると確定が無効になり、やめるで要求を送らずに閉じる。
- AC-19 (FR-4): 選んだドメインが再読み込み後の初期値になり、候補に無い保存値は先頭の候補に置き換わる。
- AC-20 (FR-5): 入力した有効な転送先が再読み込み後の初期値になり、形式不正の入力は保存されない。
- AC-21 (FR-6): 選んだ絞り込みと並び順が、再読み込み後も同じ状態で表示される。
- AC-22 (NFR-5): 本文の文字の大きさが、幅900ピクセルで15ピクセル、幅360ピクセルで18ピクセルになる。
- AC-23 (NFR-6): タッチ操作の端末として幅900ピクセルと360ピクセルで開くと、すべての文字入力欄の文字が16ピクセル以上になる。
- AC-24 (FR-10): 連携が無効の応答を受けると、照合の表示と更新ボタンが出ず、状態の確認も繰り返さない。
