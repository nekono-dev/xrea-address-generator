# LXCインストーラ 要件定義書

## 1. 目的

アプリを、UbuntuベースのLXC／LXDコンテナへ1行のcurlコマンドで導入し、導入後は常設コマンドで更新とアンインストールを行えるようにする。設定は設定ファイルで一元管理し、インストーラはCIで自動生成して頒布する。

## 2. スコープ

### 2.1 対象

- curlで取得して実行するインストーラによる導入。
- 設定ファイルの生成・保持・更新。
- 導入後の常設コマンドによる更新・アンインストール・状態表示。
- ブランチとタグのプッシュによるインストーラの自動生成。

### 2.2 対象外

- Docker Composeによる構成。
- Cloudflare Accessとアカウントの設定。
- XREAとProton Passのアクセストークンの発行。
- アプリの機能。

## 3. 前提

- なし

## 4. 機能要件

- FR-1: インストーラを、curlで取得して実行でき、埋め込んだコミットのソースだけを取得し、取得物が一致しなければ中止する。
- FR-2: 導入が、設定の検証後に、Node.js・Proton Pass CLI・アプリのビルド・専用ユーザー・systemdのサービスを導入し、トンネルのトークンがあるときはcloudflaredも導入する。
- FR-3: 導入を再実行しても、同じ状態に収束する。
- FR-4: 設定を権限600の設定ファイルに保持し、値を指定オプション、環境変数、既存の設定ファイル、既定値の順で決める。
- FR-5: 既存の設定ファイルの値を保持し、増えたキーの追記と、明示した値の上書きだけを行う。
- FR-6: 必須の設定がどこにも無いとき、何も変更せずに中止し、不足しているキー名を表示する。
- FR-7: 宣言のないキーの指定と、使えない文字を含む値を拒否する。
- FR-8: 導入後の常設コマンドで、導入時の参照名の最新へ追従して再適用してサービスを再起動し、導入情報を表示できる。
- FR-9: アンインストールで、アプリ本体・常設コマンド・取得先を削除し、設定とデータを残す。
- FR-10: 完全削除を指定したアンインストールで、さらに設定・データ・導入メタ情報・専用ユーザーを削除する。
- FR-11: アプリのサービスを、ループバックだけで待ち受けさせ、停止したときに自動で再起動する。
- FR-12: インストーラを、ブランチのプッシュでPre-releaseと成果物として、タグのプッシュでReleaseとして自動生成する。

## 5. 非機能要件

- NFR-1: 新規のUbuntuコンテナでの初回の導入を、10分以内に完了する。
- NFR-2: サービスの起動から死活確認の成功までを、30秒以内にする。
- NFR-3: コンテナの外部アドレスから接続できるアプリのポートの数を0にする。
- NFR-4: 常設コマンドによる更新の実行を、5分以内に完了する。

## 6. 受け入れ条件

- AC-1 (FR-1): 埋め込んだコミットのソースが取得先に展開され、コミットが一致しない取得物では本体が実行されずに中止される。
- AC-2 (FR-2): 新規のUbuntuコンテナで必須の設定を指定して導入した後、アプリのサービスが稼働し、cloudflaredはトークンを指定したときだけ稼働する。
- AC-3 (FR-3): 導入を2回続けて実行しても2回目が成功し、サービスの稼働状態と設定ファイルの内容が変わらない。
- AC-4 (FR-4): 設定ファイルの権限が600になり、指定オプション、環境変数、既存の設定ファイル、既定値の優先順位で値が決まる。
- AC-5 (FR-5): 設定ファイルを手で編集して導入を再実行しても、編集した値が保持され、増えたキーだけが追記される。
- AC-6 (FR-6): 必須の設定が欠けた導入が、設定ファイルもサービスも作らずに、不足しているキー名を表示して失敗する。
- AC-7 (FR-7): 宣言のないキーの指定と、アポストロフィまたは改行を含む値が、拒否される。
- AC-8 (FR-8): 新しいコミットの配布後、常設コマンドの更新で新しいコミットに追従し、増えた設定キーが追記され、サービスが再起動される。
- AC-9 (FR-8): 状態表示が、導入先・参照名・コミット・取得元・更新日時を表示する。
- AC-10 (FR-9): アンインストールの後、アプリ本体・常設コマンド・取得先が存在せず、設定とデータが残り、再導入で設定が再利用される。
- AC-11 (FR-10): 完全削除を指定したアンインストールの後、設定・データ・導入メタ情報・専用ユーザーも存在しない。
- AC-12 (FR-11): アプリのポートが、コンテナの内側のループバックでだけ応答する。
- AC-13 (FR-11): アプリのプロセスを強制終了すると、自動で再起動して死活確認が成功する。
- AC-14 (FR-12): ブランチのプッシュでPre-releaseと成果物が、タグのプッシュでReleaseが、それぞれ生成される。
- AC-15 (NFR-1): 新規のUbuntuコンテナでの初回の導入が、10分以内に完了する。
- AC-16 (NFR-2): サービスの起動から死活確認が成功するまでが、30秒以内である。
- AC-17 (NFR-3): コンテナの外部アドレスからアプリのポートへ接続できない。
- AC-18 (NFR-4): 常設コマンドによる更新が、5分以内に完了する。
