# PWA対応 要件定義書

## 1. 目的

発行・管理画面を、スマートフォンとパソコンのホーム画面へ追加して単独のアプリとして使えるようにする。画面ファイルを端末に保持して起動を速くし、APIの応答は保持せずに常にサーバの最新の状態を表示する。外部のアクセス制御の下でも、導入と再認証が妨げられないようにする。

## 2. スコープ

### 2.1 対象

- アプリの名前・アイコン・表示形式の宣言。
- 画面ファイルの端末への保存と、新しい版への切り替え。
- オフラインであることの表示。
- 宣言・画面ファイルの配信時のキャッシュの指示。

### 2.2 対象外

- APIの応答の保存と、オフラインでの一覧の閲覧・操作。
- プッシュ通知とバックグラウンドでの同期。
- 利用者の認証（外部のアクセス制御に委ねる）。

## 3. 前提

- 前提: web-ui — 端末へ保存し、ホーム画面から起動する対象の画面を提供する。

## 4. 機能要件

- FR-1: アプリの名前・短い名前・アイコン・テーマ色・単独表示の形式を宣言し、ホーム画面への追加を可能にする。
- FR-2: iOSのホーム画面に追加したときの名前・アイコン・単独表示の形式を宣言する。
- FR-3: 画面ファイルを初回の表示時に端末へ保存し、サーバへ接続できないときは保存した画面ファイルで表示する。
- FR-4: APIと死活確認の要求を端末に保存せず、常にサーバへ送る。
- FR-5: 画面の入口は通信を優先して取得し、外部のアクセス制御による転送の応答をそのままブラウザへ返す。
- FR-6: 新しい版の画面の入口を取得したとき、使われなくなった画面ファイルを端末から削除する。
- FR-7: オフラインの間は「オフラインです」と帯で表示し、接続が戻ったら帯を消して一覧を取り直す。
- FR-8: 宣言とService Workerと画面の入口はサーバで毎回検証させ、名前に版を含む画面ファイルは1年間キャッシュさせる。

## 5. 非機能要件

- NFR-1: 画面の入口の取得に3秒以内の応答が無いとき、保存した画面の入口で表示する。
- NFR-2: アイコンを192ピクセルと512ピクセルの2種類、iOS用に180ピクセルの1種類の正方形で用意する。
- NFR-3: オフラインで2回目以降に起動したとき、画面の見出しを2秒以内に表示する。

## 6. 受け入れ条件

- AC-1 (FR-1): 画面の入口から参照する宣言に、名前・短い名前・テーマ色・単独表示の形式と、192と512ピクセルのアイコンが含まれる。
- AC-2 (FR-2): 画面の入口に、iOS用のアイコン・ホーム画面での名前・単独表示の指定が含まれる。
- AC-3 (FR-3): 一度表示した後にオフラインにして再読み込みすると、画面の見出しと発行フォームが表示される。
- AC-4 (FR-4): 一覧と候補を取得した後の端末の保存領域に、APIと死活確認の応答が含まれない。
- AC-5 (FR-5): 画面の入口の要求が外部への転送の応答を返すと、保存した画面ではなく転送の応答がブラウザへ返る。
- AC-6 (FR-6): 新しい版の画面の入口を保存すると、その入口から参照されない画面ファイルが保存領域から削除される。
- AC-7 (FR-7): オフラインにすると帯が表示され、オンラインに戻すと帯が消えて一覧の要求が送信される。
- AC-8 (FR-8): 宣言・Service Worker・画面の入口の応答が毎回の検証を、版を含む画面ファイルの応答が1年間のキャッシュを指示する。
- AC-9 (NFR-1): 画面の入口の応答が3秒を超えて返らないとき、3秒時点で保存した画面の入口が返る。
- AC-10 (NFR-2): 3種類のアイコンが、宣言した大きさの正方形の画像として取得できる。
- AC-11 (NFR-3): 一度表示した後にオフラインにして再読み込みすると、2秒以内に画面の見出しが表示される。
