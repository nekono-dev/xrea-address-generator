# Docker構成 要件定義書

## 1. 目的

アプリを、Dockerの複数コンテナ（アプリとCloudflare Tunnel）として自宅のサーバに導入して運用できるようにする。外部への公開はCloudflare Tunnelだけを経由させ、設定は環境変数の記入例から与える。

## 2. スコープ

### 2.1 対象

- アプリのコンテナイメージと、Docker Composeによる2コンテナ構成。
- 環境変数の記入例。
- 死活確認と自動再起動。

### 2.2 対象外

- UbuntuベースのLXCコンテナへの導入。
- Cloudflare Accessとアカウントの設定。
- XREAとProton Passのアクセストークンの発行。

## 3. 前提

- なし

## 4. 機能要件

- FR-1: アプリのコンテナイメージを、公式配布のProton Pass CLIを同梱し、ハッシュを検証して作成する。
- FR-2: Docker Composeで、アプリとCloudflare Tunnelの2コンテナを起動する。
- FR-3: Proton Passのセッションの保存先だけを永続ボリュームにし、それ以外のデータを永続化しない。
- FR-4: 必須の環境変数をすべて含む記入例を提供する。
- FR-5: アプリを、ホストの外部ポートへ公開せず、トンネル経由でのみ接続できる状態にする。
- FR-6: アプリのプロセスが停止したとき、または死活確認が連続で失敗したとき、コンテナを自動で再起動する。

## 5. 非機能要件

- NFR-1: アプリのコンテナイメージの展開後のサイズを500メガバイト以下にする。
- NFR-2: 起動から死活確認の成功までを30秒以内にする。
- NFR-3: ホストへ公開するポートの数を0にする。

## 6. 受け入れ条件

- AC-1 (FR-1): 作成したイメージでProton Pass CLIのバージョンが表示され、ハッシュが一致しないバイナリではビルドが失敗する。
- AC-2 (FR-2): Docker Composeの起動で、アプリとCloudflare Tunnelの2コンテナが稼働する。
- AC-3 (FR-3): アプリのコンテナを作り直した後も、Proton Passのセッションが保持され、再ログインなしで取得できる。
- AC-4 (FR-4): 記入例が必須の環境変数を5個すべて含む。
- AC-5 (FR-5): ホストの外部アドレスからアプリのポートへ接続できず、トンネル経由の接続は成功する。
- AC-6 (FR-6): アプリのプロセスを強制終了すると、自動で再起動して死活確認が成功する。
- AC-7 (NFR-1): 作成したイメージの展開後のサイズが、500メガバイト以下である。
- AC-8 (NFR-2): コンテナの起動から死活確認が成功するまでが、30秒以内である。
- AC-9 (NFR-3): 稼働中のホストで、アプリに由来する待ち受けポートが0個である。
