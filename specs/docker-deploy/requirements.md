# Docker構成 要件定義書

## 1. 目的

アプリを、Dockerの複数コンテナ（XREAゲートウェイを内蔵したアプリ、Proton Pass読み取りサービス、Cloudflare Tunnel）として、セルフホストのサーバに導入して運用できるようにする。公式CLIを必要とするProton Pass読み取りサービスだけを別のイメージに分け、配備しない選択もできるようにする。設定は環境変数の記入例から与える。

## 2. スコープ

### 2.1 対象

- XREAゲートウェイを内蔵したアプリのイメージ、およびProton Pass読み取りサービスのイメージ。
- Docker Composeによる構成と、トンネルを使わないLAN用の追加定義。
- 環境変数の記入例、死活確認、自動再起動、権限の制限。

### 2.2 対象外

- LXCコンテナとベアメタルへの導入。
- Cloudflare Workersへの配備。
- Cloudflare Accessとアカウントの設定。
- XREAとProton Passの認証情報の発行。

## 3. 前提

- なし

## 4. 機能要件

- FR-1: XREAゲートウェイを内蔵したアプリを1つのイメージで、Proton Pass読み取りサービスを公式CLIを同梱した別のイメージで作成し、CLIのハッシュを検証する。
- FR-2: Docker Composeでアプリ・Cloudflare Tunnelを起動し、Proton Pass読み取りサービスは選択したときだけ起動する。
- FR-3: トンネルのトークンが空のときはCloudflare Tunnelのコンテナを起動しない。
- FR-4: Proton Passのセッションの保存先と、SQLite方式を選んだときの保存先だけを永続ボリュームにし、それ以外のデータを永続化しない。
- FR-5: 必須の環境変数と任意の環境変数をすべて含む記入例と、サーバ名の一覧の設定ファイルを提供し、ファイルを書き換えて再起動するだけで、イメージの再作成なしに一覧を変更できる。
- FR-6: 読み取りサービスを、ホストの外部ポートへ公開せず、Composeの内部ネットワークからのみ接続できる状態にする。
- FR-7: トンネルを使うとき、アプリを、ホストの外部ポートへ公開せず、トンネル経由でのみ接続できる状態にする。
- FR-8: 各コンテナのプロセスが停止したとき、または死活確認が連続で失敗したとき、コンテナを自動で再起動する。
- FR-9: トンネルを使わないとき、LAN用の追加定義でアプリのポートだけをホストの全アドレスへ公開し、HTTPでも認証情報のcookieを保持できるようにする。
- FR-10: 暗号化の秘密値が空のときComposeの起動を拒否し、読み取りサービスを選んで共有シークレットが空のときアプリの起動を拒否する。
- FR-11: アプリと読み取りサービスを、非特権ユーザー・全権限の放棄・読み取り専用のルートファイルシステムで実行する。
- FR-12: トンネルを使う構成では、環境変数ファイルの値によらず認証情報のcookieにSecure属性を付ける。

## 5. 非機能要件

- NFR-1: アプリのイメージの展開後のサイズを300メガバイト以下にする。
- NFR-2: Proton Pass読み取りサービスのイメージの展開後のサイズを500メガバイト以下にする。
- NFR-3: 起動から全コンテナの死活確認の成功までを30秒以内にする。
- NFR-4: トンネルを使うとき、ホストへ公開するポートの数を0にする。

## 6. 受け入れ条件

- AC-1 (FR-1): 読み取りサービスのイメージで公式CLIのバージョンが表示され、アプリのイメージに公式CLIが含まれず、ハッシュが一致しないバイナリではビルドが失敗する。
- AC-2 (FR-2): 読み取りサービスを選ばない起動でアプリとトンネルの2コンテナが稼働し、選んだ起動で読み取りサービスを含む3コンテナが稼働する。
- AC-3 (FR-3): トンネルのトークンが空の起動で、Cloudflare Tunnelのコンテナの数が0になる。
- AC-4 (FR-4): 読み取りサービスのコンテナを作り直した後も、Proton Passのセッションが保持され、再ログインなしで取得できる。
- AC-5 (FR-5): 記入例が必須の環境変数をすべて含み、任意の環境変数も空の値で並ぶ。
- AC-6 (FR-6): ホストの外部アドレスから読み取りサービスのポートへ接続できず、アプリのコンテナからは接続できる。
- AC-7 (FR-7): ホストの外部アドレスからアプリのポートへ接続できず、トンネル経由の接続は成功する。
- AC-8 (FR-8): 各コンテナのプロセスを強制終了すると、自動で再起動して死活確認が成功する。
- AC-9 (FR-9): LAN用の追加定義がアプリのポートだけを公開し、読み取りサービスを公開せず、HTTPの接続でcookieが保持される。
- AC-10 (FR-10): 秘密値が空のときComposeの起動が変数名を示して失敗し、読み取りサービスを選んで共有シークレットが空のときアプリが変数名を示して起動に失敗する。
- AC-11 (FR-11): アプリと読み取りサービスのコンテナが、非特権ユーザーで動き、ボリューム以外のルートファイルシステムへの書き込みが失敗する。
- AC-12 (FR-12): 環境変数ファイルにSecure属性を外す指定があっても、トンネルを使う構成のアプリがSecure属性付きのcookieを発行する。
- AC-13 (NFR-1): アプリのイメージの展開後のサイズが、300メガバイト以下である。
- AC-14 (NFR-2): 読み取りサービスのイメージの展開後のサイズが、500メガバイト以下である。
- AC-15 (NFR-3): コンテナの起動から全コンテナの死活確認が成功するまでが、30秒以内である。
- AC-16 (NFR-4): 稼働中のホストで、アプリに由来する待ち受けポートが0個である。
- AC-17 (FR-5): 設定ファイルのサーバ名を書き換えてアプリを再起動すると、サーバ名の一覧の問い合わせの応答が書き換えた内容になる。
